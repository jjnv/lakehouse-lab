# Roadmap

Este roadmap expresa prioridades, no fechas ni compromisos de entrega. Las
decisiones concretas se debaten en incidencias y pull requests.

## P0 · Proyecto abierto y gobernado

- [x] Código bajo licencia MIT.
- [x] Contenido educativo propio bajo `CC BY-SA 4.0`.
- [x] Mapa explícito de licencias y preservación de materiales de terceros.
- [x] Guías de contribución, conducta, seguridad y gobernanza.
- [x] Plantillas para incidencias y pull requests.
- [x] Exploración pública del catálogo y los módulos sin crear progreso.
- [x] Separación formal entre currículo canónico y extensiones comunitarias.

## P1 · Contribución sostenible

- [ ] Dividir el currículo en unidades por módulo con un manifiesto central.
- [ ] Unificar versión, fecha, runtime, changelog y compatibilidad editorial.
- [x] Añadir comprobaciones rápidas de contenido, enlaces, licencias y previews.
- [x] Publicar CI para lint, tipos, pruebas, build y accesibilidad.
- [ ] Registrar reproducciones independientes de laboratorios por cloud y runtime.
- [x] Formalizar la propuesta y revisión periódica de recursos comunitarios.
- [ ] Documentar arquitectura y despliegue autocontenido además de Vercel.

## P2 · Ecosistema

- [ ] Admitir rutas y colecciones comunitarias instalables.
- [ ] Añadir traducciones sin duplicar IDs ni progreso.
- [ ] Mostrar atribución y contribuciones por módulo.
- [ ] Publicar releases editoriales y notas de compatibilidad.
- [ ] Facilitar datasets sintéticos y laboratorios reproducibles.
- [x] Mejorar descubrimiento, comparación y seguimiento de recursos.

## Cómo participar

Consulta [CONTRIBUTING.md](CONTRIBUTING.md), busca una incidencia existente y
propón un cambio acotado. Las correcciones de contenido, verificaciones de
laboratorios y aclaraciones de licencias son buenos primeros aportes.
